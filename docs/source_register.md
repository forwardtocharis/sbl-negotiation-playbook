# Source register

Synthetic demonstrator built from public sources. Every source cited anywhere in this repository is
recorded here once, with a retrieval date and a reliability grade. Nothing here is legal advice and
nothing here has been validated against any institution's policy.

This file is the merge of the WP2 seed, the WP7 and WP8 rows, the WP5b rules rows and the four WP3
drafting-group fragments (`docs/research/source_register_{A,B,C,D}.md`). It is **deduplicated by
URL**: one document, one row, however many labels the library uses for it.

## Reliability grading (per `build_plan.md` section 2.1)

- **A** - primary law or regulator text.
- **B** - filed agreement or bank terms document.
- **C** - commentary, law-firm briefing, textbook, or a secondary summary that is not itself
  primary text.

`verified` is `true` only where an agent opened the actual primary or filed document, not a search
snippet or a third-party summary of it, and confirmed the statement directly. It does **not** mean
a human has reviewed the proposition: every clause, rule, flag and jurisdiction entry in this
repository is still `status: draft` or `status: stub`.

## Labelling convention

Ref labels are neutral codes. Publisher and institution names appear only inside URLs, never in
playbook prose, per `build_plan.md` section 0 rule 2. The **note** column of each row opens with
**Cited in the library as**, listing every ref label that points at that URL from a file under
`playbook/`, so a label in a clause file can be traced to its row even where the label and the row
title differ.

## Label collisions (resolved in WP12)

**Resolved.** Four `LAW-EW-*` labels each named two different documents, because WP3 group A
continued the sequence for clause 10's English trust, partnership and company sources while WP3
group C independently continued the same sequence for the financial-collateral and enforcement
sources in clauses 06, 07 and 09. Group C's sequence was kept, since it is used across three clause
files and matches the `UK-FCAR-2003` rows below, and the colliding labels in the other two files
were renamed.

In `playbook/clauses/10_capacity_authority.yaml`, onto subject-specific labels that cannot collide
with a sequence:

| old label | new label | document |
|---|---|---|
| `LAW-EW-03` | `LAW-EW-TA1925-S16` | Trustee Act 1925 s.16 |
| `LAW-EW-04` | `LAW-EW-TA2000-S31` | Trustee Act 2000 s.31 |
| `LAW-EW-05` | `LAW-EW-PA1890-S5` | Partnership Act 1890 s.5 |

In `playbook/clauses/02_conditions_precedent.yaml`, the Financial Collateral Arrangements (No. 2)
Regulations 2003 reg. 4 moved from `LAW-EW-02` to `LAW-EW-03`, which is the label clause 07 already
used for the same document. That also closes the one harmful same-document-two-labels case.

Each label was renamed everywhere it appeared in its file: the `ref:` field, the header comment
block and the jurisdiction-note prose. `LAW-EW-06` to `LAW-EW-09` were left alone; they appear only
in clause 10 and never collided.

`LAW-EW-02` (Law of Property Act 1925 s.103), `LAW-EW-03` (reg. 4), `LAW-EW-04` (reg. 17 as made)
and `LAW-EW-05` (reg. 18 as made) each now name exactly one document. Checked by script over every
`sources` entry in `playbook/**/*.yaml`: 109 distinct ref labels over 66 distinct URLs, **0 labels
naming more than one document** (4 before the rename).

35 URLs are still cited under more than one label. Those are the harmless aliases: a clause file
uses a short code (`LAW-EW-01`, `EDGAR-PB-01`) where the jurisdiction, flag and rule files use a
descriptive label (`UK-FCAR-2003 reg 3 (current)`), or the same label carries different pinpoint
article coverage in different files. Each row's **Cited in the library as** note below lists every
label in use for that document, so any label in any file traces to one row.

## Searches run, or deliberately not run, and why

Carried over from the four WP3 drafting-group fragments before those were deleted, so that the next

**Run, and the result deliberately not used.**

- *A numeric single-name concentration cap in published bank terms* (group B, for clause 04). The
  hits were broker, intermediary and explainer pages carrying unattributed ranges. None is primary
  law, a regulator text, a filed agreement or a bank's own published terms, so all would grade C
  with no traceable underlying document. No source added and no number taken; the cap stays an `X`

  `build_plan.md` placeholders rather than observations.

## Notes for later agents

- Add a row here for every new source, with the retrieval date and the grade, before citing it in
  a playbook file. Dedupe by URL, not by label.
- Do not upgrade another agent's `verified` value. If you open a document that someone else marked
  unverified, add what you read to the note and say who read what.
- A grade C hit with no traceable underlying document is worse than an honest `[VERIFY]`. Two
  drafting groups ran searches for a numeric single-name concentration cap and for Swiss
  governing-law clause practice, found only unattributed commentary, and recorded the negative
  result rather than citing it. Both negatives are in the known-gaps table above; do not repeat
  those searches expecting a different answer without a better source.
